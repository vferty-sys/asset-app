# GitHub Pages로 배포하기

이 앱은 서버가 필요 없는 웹 앱이라, GitHub Pages(무료)에 올리면 휴대폰·PC 어디서나 주소 하나로 열 수 있어요. 처음 한 번만 하면 되고 10분쯤 걸려요.

> **꼭 지켜 주세요** — 저장소에는 **앱 파일만** 올려요. 백업 파일(`asset-app-backup-….json`), 시트 주소, 실제 보유 종목 같은 개인 정보는 절대 올리지 마세요. 저장소의 `.gitignore`가 백업 파일 이름을 막아 두었지만, 웹 화면에서 파일을 직접 끌어다 올릴 때는 막지 못해요.

## 1단계. 저장소 준비하기

### 방법 A — 이 저장소를 그대로 쓸 때

앱 파일이 `main` 브랜치에 들어 있는지 확인해요. 다른 브랜치에서 작업했다면 GitHub에서 **Pull requests → New pull request**로 `main`에 합쳐 주세요. GitHub Pages는 고른 브랜치의 파일만 보여줘요.

### 방법 B — 내 계정에 새로 만들 때

1. GitHub 오른쪽 위 **+ → New repository**를 눌러요.
2. 이름을 정하고(예: `asset-app`) **Public**을 고른 뒤 **Create repository**를 눌러요.
3. 새 저장소 화면에서 **uploading an existing file**을 눌러요.
4. 앱 폴더 **안의** 파일과 폴더(`index.html`, `css`, `js`, `docs`, `icons`, `manifest.json`, `sw.js` 등)를 모두 끌어다 놓고 **Commit changes**를 눌러요. `index.html`이 저장소 맨 위에 있어야 해요.
5. 이름이 점(.)으로 시작하는 `.nojekyll` 파일은 끌어다 놓을 때 빠지기 쉬워요. 빠졌다면 **Add file → Create new file**에서 이름을 `.nojekyll`로 적고 내용은 비운 채 **Commit changes**를 눌러요. 이 파일이 없으면 앱 안의 "시트 연결 가이드"가 보이지 않아요.

무료 계정은 **공개(Public) 저장소**에서만 Pages를 쓸 수 있어요. 앱 코드에는 개인 정보가 없어서 공개해도 괜찮아요. 내 데이터는 각자 브라우저에만 저장돼요.

## 2단계. GitHub Pages 켜기

1. 저장소 위쪽 **Settings**를 누르고, 왼쪽 메뉴에서 **Pages**를 눌러요.
2. **Build and deployment → Source**에서 **Deploy from a branch**를 골라요.
3. **Branch**에서 `main`, 폴더는 `/ (root)`를 고르고 **Save**를 눌러요.
4. 1~2분 기다렸다가 새로고침하면 위쪽에 **Your site is live at …** 과 함께 주소가 보여요. 보통 `https://내아이디.github.io/저장소이름/` 형태예요.

## 3단계. 열어서 확인하기

1. 주소를 열면 "처음 오셨네요!" 안내가 떠요. **샘플 데이터로 둘러보기**를 눌러 화면이 잘 나오는지 확인해요.
2. 확인했으면 화면 위의 **샘플 지우고 내 데이터로 시작**을 눌러요.
3. 현재가를 자동으로 받으려면 [시트 연결 가이드](SHEET_SETUP.md)를 따라 해요. 연결하지 않아도 현재가를 직접 넣어 모든 기능을 쓸 수 있어요.

## 4단계. 휴대폰 홈 화면에 추가하기

- **아이폰(사파리)**: 아래쪽 공유 버튼 → **홈 화면에 추가**
- **안드로이드(크롬)**: 오른쪽 위 ⋮ 메뉴 → **홈 화면에 추가** 또는 **앱 설치**

한 번 연 뒤에는 인터넷이 잠깐 끊겨도 앱이 열려요. 시세는 마지막으로 받은 값을 보여줘요.

## 업데이트하기

- 앱 파일을 고쳐 `main`에 올리면(커밋) 1~2분 뒤 사이트에 반영돼요.
- 입력한 데이터는 각자의 브라우저에 있어서, 업데이트해도 **그대로 남아요**.
- 앱은 열 때마다 인터넷으로 새 파일이 있는지 먼저 확인해요. 새로고침 한 번이면 새 버전이 보이고, 홈 화면 앱은 완전히 닫았다가 다시 열면 돼요.
- 파일을 **새로 추가하거나 지웠다면** `sw.js`의 `APP_FILES` 목록을 함께 고치고 `CACHE_VERSION`을 올려 주세요(예: `'v1'` → `'v2'`). 오프라인용 사본이 새 목록으로 바뀌어요. `npm test`가 목록이 실제 파일과 맞는지 검사해요.
- 저장 데이터의 구조를 바꾸는 업데이트라면 `js/storage.js`의 `SCHEMA_VERSION`을 올리고 `MIGRATIONS`에 변환 함수를 추가해요. 예전 데이터는 앱을 열 때 자동으로 새 구조로 바뀌고, 바뀌기 전 원본도 브라우저 안에 따로 보관돼요.

## 꼭 알아 두세요

- **데이터는 주소와 브라우저마다 따로 저장돼요.** 같은 주소라도 다른 기기·다른 브라우저에서는 처음 화면이 나와요. 옮길 때는 설정 → 내 데이터에서 **백업 파일 내려받기** → 새 기기에서 **백업 파일로 복원**을 써요.
- **주소가 바뀌면 이전 데이터가 보이지 않아요.** 저장소 이름을 바꾸거나 다른 계정으로 옮기거나 직접 산 도메인을 연결하기 **전에** 백업 파일을 내려받고, 새 주소에서 복원해 주세요.
- **브라우저의 방문 기록·사이트 데이터를 지우면 앱 데이터도 지워져요.** 가끔 백업 파일을 내려받아 두세요.
- **지인에게 알려 줄 때**: 같은 주소를 알려 줘도 데이터는 사람마다 따로 저장돼서 섞이지 않아요. 시세 시트만 각자 만들면 돼요([시트 연결 가이드](SHEET_SETUP.md)의 "템플릿 시트 만들어 공유하기").
- **여러 사람이 쓰는 컴퓨터**에서는 다 쓴 뒤 설정 → 내 데이터 → **이 기기에서 데이터 삭제**를 눌러 주세요.

## 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 주소를 열면 404 | Pages를 켠 뒤 몇 분 기다렸는지, Branch가 `main`·`/ (root)`인지, 저장소 맨 위에 `index.html`이 있는지 |
| 화면이 깨지거나 비어 있음 | `css`, `js` 폴더가 통째로 올라갔는지, 주소 끝이 `/저장소이름/`처럼 `/`로 끝나는지 |
| 앱 안의 시트 연결 가이드가 안 보임 | 저장소 맨 위에 `.nojekyll` 파일이 있는지 |
| 고친 내용이 안 보임 | 새로고침을 두세 번, 홈 화면 앱은 완전히 닫았다가 다시 열기 |

## 내 컴퓨터에서 먼저 확인해 보기 (선택)

파이썬이 깔려 있다면 앱 폴더에서 아래 명령을 실행하고 브라우저로 `http://localhost:8000`을 열어요.

```bash
python3 -m http.server 8000
```
